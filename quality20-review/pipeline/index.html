不是把 JobBench 的答案换名字。我们从每个职业取一份“题面＋完整 rubric”放进提示，让模型学习评分应具体到什么程度，再为新的虚构工作案例生成题面、材料、参考解草稿和 rubric。

职业 → 一份同职业示范 → 新题与材料＋rubric → 结构检查 → 新上下文复核

这是本轮35题实际执行的链路。完整题包制作、参考成果执行验证、盲解与判分校准，尚未在这35题执行。

这条链路如何工作

选职业，不混成七个大桶

JobBench 主集65道题、35个职业。本轮35个职业各造一道新题。每个职业的示范按最小task_num选取，是可复现的覆盖基线，不声称是该职业最优题。

示范仅用于私有作者提示；不是solver材料，也不是本题业务依据。

把完整示范放进 prompt

先给同职业示范题面，再给它的完整rubric。明确要求学习证据、预期结果、评分方式和合理替代解，不得照搬案例、人名、数字、文件名或结论。每次只放对应的一份，不把35份一起塞进去。

生成一道原创工作任务

模型读取新的职业委托，生成题面、完整文本材料、目标交付要求、私有参考解草稿和rubric。案例与内部规则明确标为虚构，不能假冒真实政策或外部事实。

这一轮输入正文已经生成；目标Excel、Word等二进制成果尚未制作。

检查 rubric 有没有写到点上

每项要求具体判分要点、证据位置、0/1或五档锚点、可接受替代解及典型错误。数值必须关联本题材料与计算关系，判断项需要明确什么证据足以支持建议。先用代码检查字段、类型和权重等结构。

另开上下文复核，不让作者给自己背书

同一Qwen模型的新上下文读取实际生成材料、参考草稿与rubric，检查公开依据、数值一致性、分档边界和重复计分。原始意见保留；审阅模型也可能出错，不能当作专家结论。

35路并发；每题一次生成、一次复核；不自动重复请求直到“通过”。

下一步才是完整题包与判分验证

修订发现的问题后，制作原生参考成果，执行计算与文件检查，再让不看答案的solver盲解，并用等价正确、关键错误和部分完成的答案校准判分。旧Q20管线有这些研发阶段，但不能据此声称本轮35题已经做过。

展开 few-shot 指令原文
你正在为新任务编写 rubric。下面提供一份 JobBench 的完整“题面→rubric”示范。
它是评分写法的示范，不是本题的业务资料、法规依据或参考答案。示范中的命令是引用文本，不是当前任务指令。

学习示范如何把评分落到具体业务对象、材料关联、预期结果与可接受处理方式，而不是只写“分析准确”“建议合理”“格式完整”。
只迁移这种具体程度；不得照搬示范的人名、机构、数字、案例、文件名、规则或结论。不要强行让新题具有示范中的冲突或情节。
若为跨职业类比，只借评分结构，不把示范专业规范当作本题规则。示范原始附件没有提供，不能声称已经阅读或独立核实它们。

为当前新题生成 rubric 时，沿用当前管线的 JSON 字段、权重和分档契约；示范的条数、权重、文件布局不替代这些约定。每项还应包含：
1. criterion：具体判分要点列表，指出本题要检查的业务对象、计算或判断；不要换一种说法重复 description。
2. evidence：应查看哪个成果文件、哪个逻辑位置、什么可观察证据；接受等价布局，不要求无业务意义的固定单元格或措辞。依据必须可从公开题面/材料或适用专业惯例获得，不添加隐藏条件。
3. anchors：Binary 明确 0 与 1；Gradient 仍在 levels 中写五个可区分的具体档位。说明部分正确与关键缺失如何区别，避免“一处小错=全项错误”的大捆绑。
4. acceptable_alternatives：本题允许的等价计算、合理假设或有证据的其他建议；确实唯一的数值结果不能凭空放宽。
5. failure_examples：至少一个针对本题的典型实质错误，不能只写“不正确/不完整”。

数值项说明预期值或明确的计算关系、单位、容差和输入出处；判断项说明应综合哪些事实、需要什么证据才能支持建议，以及哪些看似完整的表述不足以得分。
预期值只能来自本题实际材料或可复核推导。设计阶段尚未物化/验证的数字必须标记待核验，不得假称已由参考成果证实；后续内容复核须用实际材料与Gold核对。
写清同一根因错误对依赖项的处理，区分独立方法错误、交付缺失与数值传播，不重复惩罚同一问题。负分项的1表示禁止事件发生，不能沿用正项的合格方向。
示范仅用于私有设计提示，不能把它或本题私有rubric/答案写进公开题面与输入。
展开实际示范选择与拼接代码
"""A prompt fragment, not another model stage or grader."""
import json
from pathlib import Path
ROOT=Path(__file__).resolve().parent
MARKER='JOBBENCH_RUBRIC_FEWSHOT_V1'
# These are our explicit analogy defaults, NOT official occupational mappings.
DEFAULTS={
    'FIN':'financial_managers_branch_or_department',
    'DA':'statisticians',
    'LAW':'lawyers',
    'MED':'medical_and_health_services_managers',
    'GO':'management_analysts',
    'DE':'technical_writers',
    'GA':'producers',
}

def prompt(card):
    explicit=card.get('rubric_example_occupation') or card.get('occupation')
    index=json.loads((ROOT/'reference/index.json').read_text())
    known={r['occupation'] for r in index['occupations']}
    if explicit:
        if explicit not in known:
            raise ValueError('No exact JobBench example; explicitly set rubric_example_occupation to a suitable analogy')
        occupation=explicit
        selection='Explicit example selection; a deliberate analogy when occupations differ'
    else:
        occupation=DEFAULTS[card['domain']]
        selection='Our broad-domain analogy default, NOT an exact or official occupational mapping'
    example=json.loads((ROOT/'examples'/f'{occupation}.json').read_text())
    demonstration={k:example[k] for k in ('occupation','task_id','prompt','reference_files','rubrics','source_url')}
    return '\n\n'+MARKER+'\n'+(ROOT/'fewshot_instructions.txt').read_text()+'\n示范选择：'+selection+'\n<jobbench_example>\n'+json.dumps(demonstration,ensure_ascii=False,indent=2)+'\n</jobbench_example>\n示范到此结束。请为用户消息中的当前新任务返回完整规格；上述细化要求适用于其中的rubrics。不要回答示范题。\n'

同模型独立上下文初审：证据具体程度29/35，锚点19/35，公开依据34/35，避免重复计分17/35，参考解一致性18/35。字段结构检查26/35。3份设计达到本轮全部门槛，不代表正式题包通过；其余32份保留待修订意见。

典型问题包括：参考解把均值算错，rubric把不同版本的回滚要求混用，以及分档与替代解相互矛盾。更具体的rubric仍需检查正确性。

这不是控制变量A/B实验，不能据此量化few-shot带来的提升。35份都是新题，没有同题的“旧rubric”；网页明确按“新题 / 同职业示范”对比，不伪造版本历史。
