# 运输原型的首年购车方案：预算缩减后，还值得怎么买？

你是 Hexline 工作室的系统分析师。制作人准备评审运输经营原型的首年购车推荐，希望拿到一份能解释清楚、也能复跑的决策依据，而不只是车辆收益排行榜。

财务准备了两种采购额度：10 万英镑，以及预算缩减后的 7 万英镑。请基于给定的六个运输选项，分别推荐一组可行车辆，并说明在运输变慢、需求下降的压力情景下，两种预算各能保留多少净现金。制作人尤其想知道：多投入的采购资金换来了什么，最优方案相较其他可行方案好在哪里，以及结论有哪些边界。

`routes.json`、`cargo-rates.json` 和 `planning_policy.json` 是本轮已经统一的规划输入，没有需要你追溯的审批版本。`model_contract.md` 定义本项目的计费、需求、费用、约束和同分排序规则；这是原创的有限规划模型，不是完整游戏引擎。原 Wiki 材料只供机制背景核对，不能用当前网站或引擎行为替换本项目约定。

请交付以下四份实际文件到 `/app/output/`：

- `model.py`：接受 `--inputs INPUT_DIR --output OUTPUT_DIR`，从该目录的三个 JSON 重算 `plan.json`。预算、路线、需求或其他给定参数改变后，也应使用同一程序重算；不要求采用特定求解算法。
- `plan.json`：包含两种预算的结果、各自至少前三个次优可行组合、各选项不同车数的基准/压力计算，以及预算缩减的量化比较。语义接口见 `output_contract.json`，允许额外解释字段；没有可行组合时明确报告，不伪造推荐。
- `planning.xlsx`：供分析师审计，保留来源参数、可编辑计算公式、两情景结果和组合比较。应能看清哪些计算支撑了推荐，不能只把 JSON 贴进表格；表名和布局自行决定。
- `handoff.docx`：面向制作人的中文决策说明，正文不超过两页。清楚交代两种预算下的推荐、关键收益与代价、次优取舍，以及继续评审所需的验证边界。无需重述整份技术模型。

三个成果中的共享数字必须一致。这里的“次优”按公开模型的目标排序，而不是随意挑选对照组；若不足三种，则报告实际数量。允许任何满足公开约定的等价实现与表达。

这是虚构工作室的离线设计演练：成本、路线和预算不是实际遥测或投资数据。输入只读，不联网换数据，不做真实采购，不声称已经运行或验证完整 OpenTTD 引擎，也不编造批准、测试或发布记录。
