# 核对药品召回材料，交一份内部待办清单

你是质量团队的资料复核员。团队拿到一批FDA公开召回记录，旧稿把相似包装、原包装和再包装批号混在一起，还认为Completed或Terminated就可以直接不管。请先查清材料真正支持什么，再交接需要补证的事项。

这是资料核对演练，不是临床处置。公开JSON是真实数据；20个案例、内部SOP、审批及旧稿都是原创模拟材料，不是真实医院库存或患者记录。

## 给你的材料

drug-enforcement.json保留报告日期在2024年1—2月的183条真实记录，另附官方接口说明、字段说明和使用条款及Word阅读版。网页和数据实际取得于2026-10-21，不是2024网页快照；不得重建并不存在的完整历史状态。

review-cases.json列出本轮选审的9条召回和20个待核案例。候选召回、包装标识、批号及有效期是核对输入，不代表实际持有药品。approval-events.json列版本审批。/skills/recall-text-review里的SKILL.md和policy.json包含本项目的特定匹配和内部待办规则，须先读。

## 要完成的工作

1. 按技能规定的权限、发生及收到时间选择本轮版本。保留全体原始查询的概况，并区分183条查询、9条选审、召回事件数和20个案例。
2. 逐例比较候选召回正文的包装NDC与批号。原包装与再包装必须对应；不能用补充标识字段扩大召回范围。All lots后的有效期限制必须保留，缺失信息不猜。
3. 每例给出“正文范围命中”“本条正文不足以支持命中”或“信息不足待核”，附判断依据。记录选审产品及code_info原文、分类和状态标签，不以相似名称替代包装与批号证据。
4. 对选审记录分别保留发起日、报告日、原始终止日及两日相差天数。说明数据更新时间、捕获时间和单条事件时间有什么不同；不能把接口快照当召回生命周期。
5. 根据技能的特有SOP生成内部资料待办优先级、UTC时限和负责人。只排资料复核工作，不将该时限包装成法规或临床处置时限。
6. 写中文交接：旧稿哪些判断应撤回，哪些证据仍缺、谁来补；继续完成现有资料核对。不要把未知库存或患者暴露填成0。

## 交付文件

只在/app/output交review.py、review.json、review.xlsx、handoff.docx。

review.py接受--inputs INPUT --output OUTPUT --skills SKILLS，从原始JSON及技能重算另外三份文件并保留同一程序，不复制静态答案。review.json包含有效版本/截点、原始查询概况、选审记录原文及日期、逐例结论/理由/内部待办、真实输入及技能SHA256，明确没有临床放行、公众警报或实际库存凭证。review.xlsx包含可编辑的逐例核对、原始批号证据、时间信息和内部待办，内容与JSON一致。handoff.docx为中文、不超过3页，能直接交接结论与补证责任。

## 硬性要求

不得修改原始输入或/skills，不联网换数据或补猜批号、不接触患者或厂家、不实际发布。不能依据这些数据作医疗决定、发公众警报、证明召回生命周期，或把否定匹配说成不受其他召回影响/可以恢复使用。标识前导零必须保留；不交压缩包或加密文件。保留FDA来源署名，明确演练边界。
