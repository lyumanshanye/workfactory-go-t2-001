## 一、键盘导航测试

### TC-01：全流程键盘可达性

**场景目标**：验证表单所有交互元素均可通过键盘操作完成，焦点顺序合理。

**前置条件**：
- 使用物理键盘（非鼠标）
- 浏览器窗口为标准桌面尺寸（1920×1080）
- 未开启任何辅助技术

**操作步骤**：
1. 打开表单首页（步骤1：身份验证）。
2. 按 `Tab` 键依次移动焦点，验证焦点到达每个可交互元素。
3. 在认证方式选择区域，使用方向键（↑/↓）切换单选按钮。
4. 选择"密码登录"后，按 `Tab` 到达密码输入框，输入测试密码。
5. 按 `Enter` 或 `Tab` 到登录按钮后按 `Space` 提交。
6. 进入步骤2后，继续 `Tab` 遍历所有输入框，使用 `Shift+Tab` 回退验证反向导航。
7. 依次通过步骤3和步骤4，确保"上移/下移"按钮可通过 `Tab` 到达并用 `Enter`/`Space` 激活。
8. 在步骤4的提交按钮上按 `Enter` 触发提交。

**预期结果**：
- 视觉：焦点指示器在每个元素上清晰可见（3px实线，#1A1A1A，在#F0F0F0背景上对比度≥3:1）。
- 焦点顺序：与视觉阅读顺序一致（从上到下、从左到右），无跳跃或遗漏。
- 所有按钮（上移/下移/提交/帮助）均可通过 `Enter` 或 `Space` 激活。
- 单选按钮可通过方向键切换，`Tab` 键可跳出单选组。
- 焦点不被任何固定定位元素（页眉、悬浮帮助按钮）遮挡（SC 2.4.11 验证）。
- 屏幕阅读器状态：无（本用例不使用读屏软件）。

---

### TC-02：键盘焦点不被遮挡

**场景目标**：验证 SC 2.4.11 Focus Not Obscured (Minimum) (AA)。

**前置条件**：
- 浏览器窗口高度缩小至 768px，使表单内容需要滚动。
- 页面存在固定定位的页眉（如帮助导航栏）。

**操作步骤**：
1. 在步骤2中，使用 `Tab` 键将焦点移动到手机号输入框。
2. 如果该输入框因滚动而进入视口，观察焦点元素是否被固定页眉完全遮挡。
3. 在步骤3中，使用 `Tab` 键将焦点移动到最后一张服务卡片的"下移"按钮。
4. 观察焦点是否被右下角的悬浮帮助按钮遮挡。

**预期结果**：
- 视觉：获得焦点的元素完全可见，不被任何作者创建的内容遮挡。
- 如果使用 `scroll-padding-top`，焦点元素滚动后与固定页眉之间保持足够间距。
- 无障碍树：焦点元素的 `boundingClientRect` 不被其他元素的 `z-index` 层级完全覆盖。

## 二、屏幕阅读器测试

### TC-03：表单标签与必填标识朗读

**场景目标**：验证所有表单控件的标签、必填状态和输入说明被屏幕阅读器正确朗读。

**前置条件**：
- 开启 NVDA（Windows）或 VoiceOver（macOS）
- 浏览器为 Chrome 或 Firefox

**操作步骤**：
1. 进入步骤2"基本信息"。
2. 使用 `Tab` 键将焦点移动到"姓名"输入框。
3. 继续 `Tab` 到"身份证号"输入框。
4. 继续 `Tab` 到"手机号"输入框。
5. 进入步骤3，焦点到达服务卡片区域。
6. 使用方向键或 `Tab` 遍历"上移"和"下移"按钮。

**预期结果**：
- 焦点在"姓名"输入框时，朗读内容包含：
  - "姓名，编辑框，必填"（或"姓名，编辑框，星号"）
  - 可通过 `NVDA+Ctrl+R` 或 VoiceOver `VO+F3` 朗读描述："请填写身份证上的姓名"
- 焦点在"身份证号"输入框时：
  - 朗读："身份证号，编辑框，必填"
  - 描述朗读："请输入18位身份证号码，最后一位可能是X"
- 焦点在"上移"按钮时：
  - 朗读："将助餐服务上移一位，按钮"
- 步骤3中不再出现"请再次输入姓名"的输入框（冗余输入已消除，SC 3.3.7 验证）。

---

### TC-04：错误提示朗读

**场景目标**：验证输入错误时，屏幕阅读器能正确播报错误信息。

**前置条件**：
- 开启 NVDA
- 在步骤2中

**操作步骤**：
1. 将焦点移到"身份证号"输入框。
2. 输入"12345"（格式错误）。
3. 按 `Tab` 离开该字段（触发 onBlur 校验）。
4. 等待错误提示出现。

**预期结果**：
- 视觉：输入框出现红色边框（2px）+ ⚠️ 图标 + 错误文字。
- 屏幕阅读器：自动朗读错误信息——"身份证号，编辑框，必填，无效输入。身份证号格式不正确。请输入18位数字，最后一位可能为X。"
- `aria-invalid="true"` 被设置，`aria-describedby` 关联到错误消息的 `id`。
- 错误消息容器具有 `role="alert"` 或位于 `aria-live="assertive"` 区域中。
- 老年用户特定反馈：错误提示文字字号≥16px，图标尺寸≥24×24px，背景不使用纯红色填充（避免色弱用户混淆）。

---

### TC-05：进度指示器朗读

**场景目标**：验证进度条的 ARIA 状态被正确朗读。

**前置条件**：
- 开启 VoiceOver（macOS）
- 在步骤2中

**操作步骤**：
1. 使用 VoiceOver 的 rotor 或 `Tab` 导航到进度指示器区域。
2. 使用方向键进入进度条列表。

**预期结果**：
- 朗读："表单进度，列表，4项。当前步骤，第2步，基本信息。"
- `aria-current="step"` 使当前步骤被标记为"当前"。
- 已完成步骤（步骤1）标记为 `aria-current` 移除或使用其他语义标记（如"已完成"）。
- 视觉：当前步骤数字使用高对比度填充背景（如 #2563EB 蓝底白字），已完成步骤使用不同视觉样式。

---

### TC-06：排序变化播报

**场景目标**：验证服务排序调整后，屏幕阅读器播报变化结果。

**前置条件**：
- 开启 NVDA
- 在步骤3中

**操作步骤**：
1. 将焦点移到"助浴服务"卡片的"上移"按钮。
2. 按 `Enter` 激活。

**预期结果**：
- 视觉："助浴服务"卡片位置从第2位移到第1位，优先级标签更新为"优先级 #1"。
- 屏幕阅读器：`aria-live="polite"` 区域播报——"助浴服务已移动到第1位"。
- 原"助餐服务"的优先级自动变为"优先级 #2"。
- 顶部卡片的"上移"按钮变为 `disabled` 状态，朗读为"将助餐服务上移一位，按钮，不可用"。

## 三、大字号与高对比度测试

### TC-07：系统字号放大至200%

**场景目标**：验证表单在系统字号放大后布局完整，无内容截断或重叠。

**前置条件**：
- 浏览器缩放比例设为 200%（或操作系统字号设为最大）
- 浏览器窗口宽度为 1024px

**操作步骤**：
1. 打开表单，从步骤1到步骤4逐一检查。
2. 在每个步骤中，检查所有文本是否完整显示。
3. 检查输入框、按钮、卡片是否仍然可用。
4. 水平滚动页面，检查是否有文本被截断。

**预期结果**：
- 所有文本完整显示，无截断（特别是身份证号格式说明、错误提示等长文本）。
- 布局响应式调整：卡片从横向排列变为纵向堆叠。
- 按钮保持最小 24×24 CSS pixels 的触控区域（实际物理尺寸随缩放增大）。
- 进度指示器从横向变为纵向或换行显示，文字不被裁切。
- 表单字段宽度自适应，placeholder 文字完整可见。
- 无水平滚动条（除设计允许的宽表格外）。

---

### TC-08：Windows 高对比度模式

**场景目标**：验证表单在操作系统高对比度主题下可正常使用。

**前置条件**：
- 开启 Windows 高对比度主题（设置 > 辅助功能 > 对比度主题）
- 选择"夜空"或"沙漠"主题

**操作步骤**：
1. 在高对比度模式下打开表单。
2. 逐一检查步骤1到步骤4的所有元素。
3. 触发一个输入错误，检查错误提示的显示。
4. 将焦点移到不同元素上，检查焦点指示器。

**预期结果**：
- 所有文本可见，不被背景色吞没。
- 表单控件边框清晰可见。
- 错误提示不依赖颜色区分：图标+文字+边框变化均可见。
- 焦点指示器在高对比度下仍然可见（可能由系统覆盖为系统级焦点样式）。
- 按钮文字与背景对比度足够。
- `forced-colors: active` 媒体查询正确响应，不覆盖系统强制颜色。

## 四、认证与超时测试

### TC-09：替代认证方式可用性

**场景目标**：验证 SC 3.3.8 — 认证不依赖认知记忆。

**前置条件**：
- 一位不记得密码的测试用户（模拟认知障碍老年人）

**操作步骤**：
1. 打开表单步骤1。
2. 选择"手机短信验证码"认证方式。
3. 输入手机号，获取验证码。
4. 输入6位验证码，完成登录。
5. 另起测试：选择"社区服务卡刷卡"方式，模拟NFC刷卡。
6. 另起测试：查看是否有"线下协助"入口。

**预期结果**：
- 短信验证码流程：6位数字输入，有效期≥5分钟，发送后有明确倒计时提示。
- 刷卡流程：NFC读卡成功或二维码扫描成功后直接进入步骤2。
- 线下协助：页面底部或帮助区域有明确的热线电话和地址信息。
- 所有替代方式均不需要用户记忆8位复杂密码。
- 屏幕阅读器朗读："请选择登录方式，分组。手机短信验证码，单选按钮，已选中。"

---

### TC-10：超时预警与延长

**场景目标**：验证超时机制对老年用户友好。

**前置条件**：
- 在步骤2中填写了部分信息
- 等待超时预警触发

**操作步骤**：
1. 在步骤2输入姓名后停止操作。
2. 等待至超时前2分钟，观察是否弹出预警。
3. 在预警对话框中点击"继续操作"。
4. 继续填写信息。
5. 模拟故意超时（不点击延长），观察超时后行为。

**预期结果**：
- 预警对话框以 `role="alertdialog"` 呈现，焦点自动移到对话框内的"继续操作"按钮。
- 倒计时数字每秒更新，使用 `aria-live` 区域播报剩余时间（或仅视觉显示，避免频繁朗读干扰）。
- 点击"继续操作"后，对话框关闭，焦点返回到之前正在编辑的输入框。
- 已填写数据不丢失。
- 如果超时发生：不自动清空数据，而是显示"您的会话已过期，但您之前填写的信息已保存。点击此处恢复。"
- 老年用户特定反馈：预警对话框字号≥18px，按钮尺寸≥44×44px，使用明确的图标（⏰ 时钟）和文字"会话即将过期"。

## 五、老年用户特定场景测试

### TC-11：误触后的撤销操作

**场景目标**：验证老年用户误操作后可撤销。

**前置条件**：
- 在步骤4确认提交页面

**操作步骤**：
1. 误按"确认提交"按钮。
2. 在确认对话框中点击"返回修改"。
3. 验证是否回到步骤3，且之前所有数据保留。
4. 提交成功后，检查是否有"撤销预约"选项。

**预期结果**：
- 确认对话框出现，提供明确的"确认提交"和"返回修改"两个选项。
- 点击"返回修改"后回到步骤3，所有服务选择和排序保持不变。
- 提交成功后显示成功页面，包含：
  - 预约编号
  - 已选服务摘要
  - "撤销预约"按钮（24小时内可撤销）
  - "返回首页"按钮
- 屏幕阅读器朗读："提交成功。您的预约编号为XXXXXX。助餐服务，优先级1。助医服务，优先级2。"
- 成功提示使用大字号（≥20px）、高对比度成功图标（✓）和文字双重确认。

---

### TC-12：帮助入口一致性

**场景目标**：验证 SC 3.2.6 — 帮助机制在所有步骤中位置一致。

**前置条件**：
- 无特殊配置

**操作步骤**：
1. 在步骤1中找到帮助入口，记录其视觉位置和DOM顺序。
2. 进入步骤2，找到帮助入口，比较位置。
3. 依次检查步骤3和步骤4。
4. 点击帮助入口中的"服务热线"链接，验证是否可一键拨号。

**预期结果**：
- 所有4个步骤中，帮助入口出现在相同的相对位置（如页面右下角或页脚）。
- DOM顺序一致（在页面源码中的位置相同）。
- 帮助入口包含：电话热线、常见问题、视频指南、在线客服、线下地址。
- 电话链接使用 `tel:` 协议，在移动设备上可直接拨号。
- 屏幕阅读器朗读："帮助与支持，导航。拨打服务热线400-XXX-XXXX，链接。"

### TC-13：放大镜用户场景

**场景目标**：验证使用系统放大镜的老年用户可完成表单。

**前置条件**：
- 开启 Windows 放大镜（Win + '+'），放大倍率 300%
- 或使用 macOS Zoom（Option + Command + '+'）

**操作步骤**：
1. 在放大镜模式下进入表单。
2. 使用 `Tab` 键导航，观察焦点元素是否随放大镜自动滚动到视口中心。
3. 在步骤3中调整服务排序，确认卡片按钮在放大状态下可见且可点击。
4. 检查固定定位元素（如帮助按钮）是否随放大镜移动或保持固定。

**预期结果**：
- 焦点元素自动滚动到视口中心或至少可见区域。
- 放大后文本清晰可读，无模糊或像素化。
- 按钮在放大后仍然在预期位置，不发生布局错位。
- 固定元素在放大后不会遮挡焦点元素（SC 2.4.11 在放大状态下也需满足）。
- 进度指示器在放大后仍然完整可见或合理折叠。

## 六、冗余输入消除验证

### TC-14：步骤3不再要求重复输入

**场景目标**：验证 SC 3.3.7 — 消除冗余输入。

**前置条件**：
- 在步骤2中填写了姓名"张三"、身份证号"310101195001011234"、手机号"13812345678"

**操作步骤**：
1. 进入步骤3。
2. 检查页面是否包含"请再次输入姓名"和"请再次输入身份证号"的输入框。
3. 检查是否展示已填写信息的只读确认视图。
4. 点击"信息有误？返回修改"按钮。
5. 验证返回步骤2后数据是否保留。

**预期结果**：
- 步骤3中**不存在**任何要求重复输入姓名或身份证号的文本输入框。
- 展示只读信息摘要："姓名：张三"、"身份证号：310***********1234"（脱敏显示）。
- 信息摘要使用 `<dl>`/`<dt>`/`<dd>` 语义结构。
- 屏幕阅读器朗读："确认您的身份信息。姓名，张三。身份证号，310星号星号星号星号星号星号星号星号星号星号1234。"
- 点击"返回修改"后跳转步骤2，所有字段保留原始值。
- 无障碍树中不存在多余的 `textbox` 角色元素。
