# 线下设备借用自助终端 · 原型交接文档

> 版本：1.0 | 创建日期：2024-05-15 | 合规目标：WCAG 2.2 AA 级

---

## 1. 原型概述

本原型为一个单文件 HTML 可交互页面（`kiosk_borrow_prototype.html`），模拟园区大堂"线下设备借用自助终端"的完整操作流程。所有状态和数据均在前端模拟（使用 JS 内存变量 + localStorage），**无需任何网络连接**即可运行。

### 1.1 业务流程

| 步骤 | 名称 | 说明 |
|------|------|------|
| 1 | 身份验证 | 员工模拟 NFC 刷卡 / 访客手机号 + 6 位数字验证码 |
| 2 | 选择设备 | iPad Pro、VR 头显、微单相机，各初始 2 台 |
| 3 | 填写详情 | 借用用途 + 预计归还时间（联系信息自动填入） |
| 4 | 确认借用 | 信息摘要核对 → 提交 → 库存扣减 |

### 1.2 设备库存

| 设备 | 初始库存 | 状态管理 |
|------|---------|---------|
| iPad Pro 12.9" | 2 台 | localStorage 持久化 |
| VR 头显 (Meta Quest 3) | 2 台 | localStorage 持久化 |
| 微单相机 (Sony A7IV) | 2 台 | localStorage 持久化 |

## 2. 离线运行与测试指南

### 2.1 运行方式

1. 将 `kiosk_borrow_prototype.html` 文件拷贝到任意位置。
2. 使用任意现代浏览器（Chrome / Firefox / Edge / Safari）直接双击打开。
3. **无需 HTTP 服务器、无需网络连接、无外部依赖**。

### 2.2 离线验证方法

- 打开浏览器开发者工具（F12）→ Network 标签 → 勾选 "Offline"。
- 完成完整借用流程，确认所有功能正常。
- 关闭浏览器后重新打开，检查设备库存状态是否通过 localStorage 正确持久化。

### 2.3 键盘无障碍测试

- 使用 `Tab` / `Shift+Tab` 遍历所有交互元素。
- 确认焦点顺序逻辑合理，焦点指示器清晰可见。
- 打开帮助弹窗后，确认 `Tab` 键被限制在弹窗内部（焦点陷阱）。
- 按 `Escape` 关闭弹窗，确认焦点返回触发按钮。

### 2.4 清除数据

如需重置所有模拟数据：
- 打开开发者工具 → Application → Local Storage → 清除当前页面数据。
- 或刷新页面时按住 `Ctrl+Shift+Delete` 清除站点数据。

## 3. WCAG 2.2 合规性映射

以下为原型中具体实施的 WCAG 2.2 新增准则及其实现方式：

### 3.1 §2.4.11 Focus Not Obscured (Minimum) — AA

**要求**：当组件获得键盘焦点时，不被作者创建的内容完全遮挡。

**实现方式**：
- 顶部栏（`.top-bar`）和步骤指示器（`.step-indicator`）均**不使用 `position: fixed`**，采用正常文档流布局（`flex-shrink: 0`）。
- 底部状态栏（`.status-bar`）虽为 `position: fixed`，但通过 `body { padding-bottom: 50px }` 确保内容区域不会被遮挡。
- 帮助模态框（`#helpModal`）使用 `z-index: 1000`，但在打开时通过焦点陷阱确保用户操作不会意外触发背景元素的聚焦。

**验证方法**：使用键盘 Tab 遍历所有步骤，确认每个输入框和按钮的焦点指示器完全可见，不被固定元素遮挡。

---

### 3.2 §2.5.8 Target Size (Minimum) — AA

**要求**：指针输入目标尺寸至少 24×24 CSS 像素。

**实现方式**：
- **自助终端增强设计**：考虑到用户可能戴手套或手指较粗（参见用户研究），所有交互目标尺寸远超最低要求：
  - 按钮（`.btn`）：`min-height: 56px; min-width: 140px`
  - 输入框：`min-height: 52px; padding: 14px 16px`
  - 帮助按钮（`.help-btn`）：`min-height: 56px; min-width: 140px`
  - 设备卡片（`.device-card`）：`min-height: 80px`
  - 认证选项卡（`.auth-tab`）：`min-height: 64px`
  - 关闭按钮：`48×48px`
- **间距设计**：相邻可点击元素之间保持至少 16px 间距（`gap: 16px`），防止误触。
- 基础字号设置为 `18px`（而非默认 16px），提升触屏可读性。

**验证方法**：使用浏览器开发者工具测量各交互目标的实际尺寸，确认均 ≥ 24×24px（实际均 ≥ 48×48px）。

---

### 3.3 §3.2.6 Consistent Help — A

**要求**：如果网站提供帮助机制，该机制在所有页面中以相同的相对顺序出现。

**实现方式**：
- **"获取帮助"按钮**（`.help-btn`）始终位于顶部栏的**右侧**（通过 CSS `order: 2` 和 Flex 布局确保 DOM 顺序与视觉位置一致）。
- 在所有 4 个步骤及完成页中，该按钮始终可见且位置不变。
- 帮助内容包含：管理员联系方式（电话、邮箱、物理位置）、操作步骤图文指引、常见问题解答。

**验证方法**：依次切换到每个步骤，确认帮助按钮始终在右上角，点击后弹出的帮助内容一致且完整。

---

### 3.4 §3.3.7 Redundant Entry — A

**要求**：同一流程中需要再次输入的相同信息必须自动填充或可选择。

**实现方式**：
- 步骤 1（身份验证）中获取的用户信息（姓名、联系方式）在步骤 3（借用详情）中**自动填入**对应字段。
- 自动填入的字段**不是只读的**（无 `disabled` 属性），用户可以修改纠正错误信息。
- 步骤 4（确认页）中展示的所有信息均来自前序步骤的输入，**不要求用户重新输入**任何信息。
- 数据通过 JS 内存变量 `userState` 在步骤间传递。

**验证方法**：完成身份验证后进入步骤 3，确认姓名和联系方式已自动填入且可编辑。

---

### 3.5 §3.3.8 Accessible Authentication (Minimum) — AA

**要求**：认证过程不得要求认知功能测试（如记忆密码），除非提供替代方案。

**实现方式**：
- **员工认证**：模拟 NFC 刷卡（点击按钮即可），无需记忆任何密码。
- **访客认证**：手机号 + 6 位短信验证码。验证码仅需输入任意 6 位纯数字，不涉及记忆任务。
- **无密码输入**：整个认证流程中**没有 `type="password"` 的输入框**，不要求用户记忆或复述任何信息。
- **错误恢复**：验证码输入失败时，手机号字段内容保留，用户无需重新输入手机号。错误提示明确指出问题所在及修正方式。

**验证方法**：
1. 作为访客，输入错误验证码（如 "12345" 只有 5 位），确认手机号保留且错误提示清晰。
2. 输入含非数字字符的验证码（如 "12345a"），确认错误提示正确。

## 4. 表单无障碍实现（基于 WAI Forms 指南）

### 4.1 标签关联

- 所有 `<input>` 和 `<textarea>` 均有对应的 `<label>` 元素，通过 `for` 属性关联。
- 每个输入框下方提供 `<span class="form-hint">` 说明文本，通过 `aria-describedby` 关联到输入控件。

### 4.2 分组语义

- 使用 `<fieldset>` 和 `<legend>` 对表单控件进行逻辑分组。
- 设备选择区域使用 `role="radiogroup"` 和 `role="radio"` 实现语义化单选。
- 身份验证选项卡使用 `role="tablist"` / `role="tab"` / `role="region"` 模式。

### 4.3 验证与错误提示

- 错误提示使用 `role="alert"` 和 `aria-live="assertive"` 确保屏幕阅读器即时播报。
- 状态消息使用 `role="status"` 和 `aria-live="polite"`。
- 输入框出错时添加 `.error` 类（红色边框）提供视觉反馈。

## 5. 焦点管理

### 5.1 模态框焦点陷阱

帮助弹窗打开时：
- 焦点立即转移到关闭按钮（`#helpClose`）。
- `Tab` 键被限制在弹窗内的可聚焦元素之间循环。
- `Shift+Tab` 同样被限制。
- 按 `Escape` 键关闭弹窗。
- 关闭后焦点**返回触发元素**（帮助按钮 `#helpBtn`）。

### 5.2 步骤切换焦点管理

每次切换到新步骤时，焦点自动转移到该步骤的标题元素（`h2`），确保屏幕阅读器用户能感知页面变化。

## 6. 技术限制与已知边界

| 项目 | 说明 |
|------|------|
| 合规级别 | WCAG 2.2 AA 级（非 AAA） |
| 焦点外观 (§2.4.13) | 使用浏览器默认焦点样式 + 自定义 outline，未严格满足 AAA 级对比度要求 |
| 拖拽操作 (§2.5.7) | 原型中无拖拽交互，自动合规 |
| 超时机制 | 自助终端场景未实现超时自动注销（业务规则未要求） |
| 多语言 | 仅支持中文，未实现 `lang` 属性切换 |
| 高对比度模式 | 颜色方案考虑了基础对比度，但未针对 Windows 高对比度模式做专项测试 |
| 屏幕阅读器 | 建议使用 NVDA + Firefox 或 VoiceOver + Safari 进行实际验证 |
